{%- comment -%} One chip on the Trajectory work grid, drawn from a document's `arc` front matter. Projects and experiences render through here identically, so every item on the chart carries the same two affordances: a hover popover with its dates and a one-line description, and a click that opens the document's detail modal. p the document (a _projects or _experience entry) work_end the grid line the fixed scale ends on, for arc.ongoing chips Front matter read here: arc.lane research | data | software — which color family the chip takes arc.tone overrides lane for color only (a research role in the data palette) arc.row grid row, 2–7 arc.start decimal year the chip begins (2023.5 = mid-2023) arc.end decimal year it ends; omitted when arc.ongoing is set arc.ongoing runs off the fixed scale into the junction instead of ending arc.kind paper | cli — draws the chip as an icon-only mini instead arc.label the chip's title arc.sub short technical tagline under the title arc.span human-readable dates, shown in the popover arc.blurb one sentence, shown in the popover arc.phases optional list of activity phases inside one chip, for work that ran hot and cold rather than at one pitch throughout. Solid = active, diagonal hatch = backburner. Each phase takes: start decimal year the phase begins end optional — defaults to the next phase's start, so a contiguous history only has to date each turn; the last phase defaults to the chip's own end cadence active (default) or backburner span display string for the phase's line in the popover note a sentence on what the work looked like in that phase Unlike the toolchain band's `segments`, phases do NOT set the chip's extent — arc.start / arc.end still do, and phases only texture what is already drawn, clipped to it. Phases must be in date order and disjoint (touching is fine, gaps are fine); a violation, or phases on an arc.kind mini, fails the build with a missing-include error naming the document and the rule.
