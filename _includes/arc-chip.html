{%- comment -%} One chip on the Trajectory work grid, drawn from a document's `arc` front matter. Projects and experiences render through here identically, so every item on the chart carries the same two affordances: a hover popover with its dates and a one-line description, and a click that opens the document's detail modal. p the document (a _projects or _experience entry) work_end the grid line the fixed scale ends on, for arc.ongoing chips Front matter read here: arc.lane research | data | software — which color family the chip takes arc.tone overrides lane for color only (a research role in the data palette) arc.row grid row, 2–8. Also picks the lane column on the narrow chart, where several rows share one — see the packing table below. arc.between the chip hangs centered in the clear space between the bars above and below it rather than on its own row's midline. For the unbanded row, whose whole point is that what sits there belongs to neither side of it. Purely visual: the chip keeps its row and only overhangs into the next one's band, so set it on every chip in the row — and on whatever else is drawn around them, or the outline slides off what it encloses. See .arc-chip.is-between. arc.relay true for chips that share a row as one continuous succession (SSPI research → BRG → IRLE engineering). They stretch to a common height instead of each hugging its own text, so a two-line label can't leave its neighbours sitting short — the run should read as one line across the chart. Set it on every chip in the row, not just the tall one. arc.start decimal year the chip begins (2023.5 = mid-2023) arc.end decimal year it ends; omitted when arc.ongoing is set arc.ongoing runs off the fixed scale into the junction instead of ending arc.kind paper | cli | web — draws the chip as an icon-only mini instead arc.label the chip's title arc.sub short technical tagline under the title arc.span human-readable dates, shown in the popover arc.blurb one sentence, shown in the popover arc.parts optional list of sections of one document drawn as separate boxes on its row rather than as one bar, for work that changed in kind partway through — a role that became a different role over the same project. Each part is a chip in its own right: its own extent, its own title, its own hover popover, all clicking through to this one document's card. Unlike phases, which only texture the bar, parts replace it — declaring both fails the build, and so does declaring parts on an arc.kind mini. Each takes: start decimal year the part begins end optional — defaults to the next part's start, so a contiguous succession only has to date each turn; the last part defaults to the chip's own end (or runs to the junction under arc.ongoing) label the part's title; falls back to arc.label sub short tagline under it; falls back to arc.sub span human-readable dates for the popover; falls back to arc.span blurb one sentence for the popover; falls back to arc.blurb Parts must be in date order and disjoint (touching is fine, gaps are fine); a violation fails the build with a missing-include error naming the document and the rule. arc.phases optional list of activity phases inside one chip, for work that ran hot and cold rather than at one pitch throughout. Solid = active, diagonal hatch = backburner. Each phase takes: start decimal year the phase begins end optional — defaults to the next phase's start, so a contiguous history only has to date each turn; the last phase defaults to the chip's own end cadence active (default) or backburner span display string for the phase's line in the popover note a sentence on what the work looked like in that phase Unlike the toolchain band's `segments`, phases do NOT set the chip's extent — arc.start / arc.end still do, and phases only texture what is already drawn, clipped to it.
